## 現在できること

| 入口 | 入力・返り値 | 人の確認との関係 |
| --- | --- | --- |
| 構造 CLI / Python コア | `mazeproof problem.json --solution solution.json` / `core.validate_structure`。格子・壁・入口出口・道順を含む構造 JSON を検証し、各検査、理由、座標、反例を返す | JSON に対する検査。画像・印刷物の品質を証明しない |
| 画像 CLI | `mazeproof inspect problem.png --solution solution.png`。PNG/JPEG/PDF の明示ページ、格子・回転設定、参照 JSON に対応。結果 JSON と、指定時に新規 `.mazeproof` ファイルを保存 | 未確認画像は `NEEDS_REVIEW`、終了コード 2。GUI で修正・承認できる。既存出力は上書きしない |
| GUI | 問題画像と任意の解答画像の 1 組を認識し、重ね表示・修正・承認・保存 | 全体の目視照合と明示承認が必要。編集・復元後は再承認 |
| MCP | 下表の読取り専用 stdio ツール 4 個 | 画像を承認する機能はない |

一括投入、フォルダからのペア作成、PDF 全ページの自動ペア化、検品一覧、進捗と中断再開、複数件の集計レポートはない。サーバーの複数ワークスペース保持は一括検品 UI ではなく、MCP の直近結果キャッシュも永続ジョブ管理ではない。

### MCP の実際の契約

| ツール | 入力 | 返すもの・制約 |
| --- | --- | --- |
| `validate_structure` | 問題・任意の解答の **JSON 文字列**、`unique_required` | コアと同じ構造検査結果。ファイルや画像は読まない |
| `inspect_file` | 許可ディレクトリ内の絶対パス、任意の PDF ページ・格子・回転 | 問題 1 枚の認識モデル、unknown 境界、変換、digest、未承認結果。唯一解は必須。解答単独の赤線認識ツールではない |
| `validate_pair` | 問題・解答の絶対パス、各 PDF ページ、`unique_required` | 両画像を独立認識した観測と未承認結果。現状、格子・回転の個別指定や参照 JSON は受け取らない |
| `get_result` | `requestId` | 同じ MCP プロセスで保持する直近 8 件のうち 1 件。再起動後の復元はない |

`tools/call` の `content[].text` に JSON で `{result, observations?}` を返す。観測から画像バイト列とファイル名を除外しているので、AI がこれだけを読んで原画像を目視確認したことにはできない。`isError: false` は合格を意味せず、`NEEDS_REVIEW` や検査上の `FAIL` も含む。利用側は `overallStatus`、`recognition.assurance`、各検査の `status` と未検査範囲を読む必要がある。

許可 root、通常ファイル、サイズ・worker 時間/RSS 制限があり、URL・symlink・root 外・FIFO は拒否する。承認ツールや `confirmed: true` の受入れはない。保存済みレポートを人の承認として取り込む機能もない。人が承認した結果を AI へ渡すなら、現状は保存レポートを参照できるだけで、改変不能な証明書として扱えない。

## 推奨する最小の実用拡張

**一括認識と、確認すべき順番を整理する検品一覧を、同じ共通処理から提供する。** 最初から人・AI 向けに別の検査ロジックを作らない。

1. **明示的な入力一覧。** 1 行ごとに ID・問題・任意の解答・PDF ページ・任意の元構造 JSON・格子設定・唯一解方針を持つ。ファイル名でのペア候補は提示しても、対応を勝手に確定しない。
2. **共通の一括処理と CLI。** まず直列または少数同時処理で上限を管理。1 件の破損で全件を止めず、各件の状態・理由・digest と集計、GUI で開ける作業を保存する。処理済み結果を残し、取消・再開と入力変更時の再検査を扱う。
3. **GUI の検品一覧。** 認識エラー、暫定 FAIL、不確かな境界ありを優先表示し、既存の修正画面へつなぐ。前後の画像へ移動し、確認・修正・明示承認・未確認のまま保留ができるようにする。件数だけで一括承認しない。
4. **同じ共通処理の MCP 窓口。** 小さく上限を設けたバッチ入力と結果取得を AI から使えるようにする。CLI/GUI/MCP の結果契約と検査方針を統一する。AI は投入、進捗確認、原因の集計、次の確認対象の案内を担当できる。MCP の許可 root と読取り専用範囲を維持し、保存が必要な経路は明示的な出力指定として別に設計する。

これはファイルの選び直し、待ち時間、結果の転記を減らす案であり、画像全体の照合を自動的に省略する案ではない。確認箇所 0・高い認識信頼度・AI の同意だけでは画像を PASS にしない。

MazeMa から元構造 JSON を出せるなら、到達性・唯一解・解答の合法性を構造段階で全件検査する入口にも価値がある。ただし、その JSON が正しくても完成画像が一致する保証にはならない。描画との照合・認識の確証は別項目として残す。MazeMa 側の出力対応はこの調査では確認していない。

## 次段階の完成条件案

- 合成 100 件に正常、別解、壁横断、問題/解答の差、曖昧画像、破損、欠けたペアを混ぜ、**件数の欠落なし・未承認画像の総合 PASS 0 件**を確認する。
- 正規化した入力と方針が同じなら、GUI/CLI/MCP の状態・checks・反例が一致する。
- 取消・途中終了・再開で完了分を失わず、入力や方針が変わると古い承認・結果を再利用しない。
- 実際の MCP クライアントを接続して、構造検査・画像の確認待ち・不正入力・結果取得の一連操作を確認する。新規登録は利用者の承認後に行う。
- 同じ迷路セットを従来の 1 枚ずつの操作と新方式で試し、人の操作回数、確認時間、見落としを比較する。速くなったかは測定し、未測定の削減率は約束しない。
