# MazeProof 操作体験デモ

公開先は [https://yo4e.github.io/MazeProof/](https://yo4e.github.io/MazeProof/)。ローカル版の導入前に、どこを見比べ、何を人が確認するのかを体験するための静的サイトです。本体の公開版 [v0.2.0](https://github.com/yo4e/MazeProof/releases/tag/v0.2.0) と区別します。導入ボタンは、ZIP・wheel・ソース配布物と手順を掲載したReleaseへ案内します。通常リリースへの切替によって、デモの検査範囲や画像認識の保証が広がるわけではありません。

## できること

正常な例、通路を壁として読み違えた例、赤線が途切れた例の3つ。原画像と重ね表示、問題／解答の切替、注目点の拡大、決まった修正例と結果例、確認担当者向けのレポート例、最初からのやり直しに対応します。320px以上の画面とキーボード操作を検証対象にします。

ファイル入力、自由編集、画像認識API、ローカルサーバー接続、MCP、人の承認、保存した作業の読込みはありません。結果を任意の入力へ使い回す操作もありません。リロードすると最初の例へ戻ります。画像を取得できない場合は説明を表示し、操作を無効にします。

## サンプルと結果の根拠

画像は `mazeproof.samples` のMIT合成素材から生成します。商品画像や利用者データは使いません。壁の例は説明のために余分な壁を1つ加え、赤線の例は原画像の一部を消し、対応する通り道のセルを1つ除きます。画像認識を実行した結果と称さず、定義した構造の検査結果だけを本体の `validate_structure` で計算します。

| 例 | 出口への到達 | 解答が1通り | 赤線の合法性 | 問題と解答の壁 |
| --- | --- | --- | --- | --- |
| 正常 | 成功 | 成功 | 成功 | 一致 |
| 余分な壁・修正前 | 不成功 | 不成功 | 壁を横断 | 一致 |
| 赤線途切れ・修正前 | 成功 | 成功 | 非連続 | 一致 |
| 決められた修正後 | 成功 | 成功 | 成功 | 一致 |

この表は合成した構造に対する計算結果です。画像の自動認識精度、人による確認済みの状態、実際の検品時間の改善を意味しません。デモには全体の合格表示や承認操作を置きません。

## ビルドと検証

開発用の依存を導入済みの環境で実行します。

```sh
python scripts/build_demo.py
python -m playwright install --with-deps chromium
python scripts/demo_e2e.py
```

ビルドは専用の `_site/` を作り直し、HTML・CSS・JS・アイコン・合成PNG3枚・出典情報だけを置きます。公開対象のファイル名は明示的に限定しています。Python本体、リポジトリ全体、`.evidence/`、作業ファイル、個人のパスや接続トークンは公開物に含めません。ページは外部フォント・解析スクリプト・外部APIを使いません。GitHub Pages自体への通常のページ取得は発生します。

UI検証は一時フォルダ内の配信物を `/MazeProof/` というサブパスで配信し、専用ヘッドレスブラウザで行います。試験用サーバーは終了時に停止します。利用者の検品サーバーは使いません。今回のMacでは新しいブラウザ起動やサーバー起動を行わず、GitHub Actionsでこの検証を行う方針です。

試験対象は3例の表示、切替・拡大、修正前後の結果、原画像の変更範囲、やり直し、反復、リロード、画像読込み失敗からの復帰、キーボード、320・375・768・1024・1440pxの表示幅、導入リンク、画像入力やAPI送信がないこと。スクリーンショットと結果JSONをActionsのartifactに14日保存します。

公開後は同じ操作試験を実際のHTTPS URLへ実行し、導入リンクのHTTP応答も確認します。

```sh
python scripts/demo_e2e.py --url https://yo4e.github.io/MazeProof/ --output .evidence/demo-public
```

## 配信

Pagesの配信元はGitHub Actions。専用workflowがビルド・UI検証の成功後に `_site/` のみをアップロードします。配信jobはmainに限定し、そのjobだけに `pages: write` と `id-token: write` を与えます。検証jobは `contents: read`。長期秘密鍵、独自ドメイン、課金サービスは追加しません。

`workflow_dispatch` で同じmainから再実行できます。デプロイ成功後にも公開URLを検証するため、配信成功と公開画面の検証成功はActions上で別に確認できます。最新結果は [Static demo workflow](https://github.com/yo4e/MazeProof/actions/workflows/demo.yml) を参照してください。
